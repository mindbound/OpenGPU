# 05 — Development stack, dependencies, and headless testing with ocelot-brain

Researcher: dev-stack track. Date: 2026-10-08. Scope: GTNHGradle setup for OpenGPU, dependency coordinates, Java 8 + runtime bytecode generation constraints, dev runs (incl. Angelica and Java 17–25), ocelot-brain as a headless harness, test layout, licensing. All `path:line` citations refer to the local checkouts listed in the brief; versions are stated where the checkout and the installed jar differ.

## Summary

- Change `modName`, `modId`, `modGroup`, `generateGradleTokenClass` (and set `apiPackage = api` if an API jar is wanted) in `gradle.properties`; the rest of the starter is correct as-is (`enableModernJavaSyntax = jabel`, `usesMixins = false`). GTNHGradle 2.0.33, Gradle 9.7.1, JDK 17 toolchain for jabel.
- OC dependency: `com.github.GTNewHorizons:OpenComputers:1.12.64-GTNH` exists on the GTNH nexus with `-dev`, `-api`, `-sources` classifiers. OC-LuaJIT uses `devOnlyNonPublishable(...:1.12.58-GTNH:dev)`. Compile against ≥ 1.12.58: `api.internal.TextBuffer.dropFile` changed signature (`String` → `byte[]` content) at 1.12.58, so the local 1.12.55 checkout is not a valid API reference for anything implementing OC's `TextBuffer`. Angelica `2.2.21` has `-api`/`-dev` too; OC itself compiles against `Angelica:2.1.52:api`. No Forgelin/Scala needed: OC runs on Forge's bundled scala-library 2.11.1 and declares no Forgelin; GTNHGradle's Scala module only activates for `src/main/scala` or `gtnh.modules.scala.forceEnable = true`.
- Bytecode generation at runtime: on the Java 8/LWJGL 2 path the only public ASM is `asm-all-5.0.3` (ASM5 API, V1_8 max); UniMixins carries ASM 9 only relocated under `org.spongepowered.asm.lib`; on the Java 17–25 lwjgl3ify path the launcher instead provides an unrelocated ASM 9.x. `LaunchClassLoader` loads `org.objectweb.asm.` parent-first, so whatever ASM the launcher provides always wins over one in a mod jar. Shade+**relocate** your own ASM 9 (OC-Wasm precedent) and define classes through a private `ClassLoader` subclass (works on Java 8 and 17–25; bypasses LaunchClassLoader transformers/Mixin).
- Dev runs: OC's dev jar carries all 27 `libjnlua*` natives and `LuaStateFactory` extracts them from the classpath into the working directory (`run/client`; `java.io.tmpdir` only with `nativeInTmpDir = true`, default `false`), so `runClient` works out of the box (OC-LuaJIT does exactly this). Angelica in dev requires `forceEnableMixins = true` + GTNHLib; `runClient17/21/25` tasks exist (lwjgl3ify + RfbSystemClassLoader + `--add-opens` list + hotswap agent; the cached plugin 2.0.20 pins lwjgl3ify 3.0.10, the 2.0.33 convention the starter uses pins 3.0.33).
- ocelot-brain reshapes the OC API into `totoro.ocelot.brain.*` (Scala traits, `Arguments` is a class, `load(nbt, workspace)`, no item/driver layer): an `li.cil.oc.api` component does **not** run unchanged. Build a pure-Java core + two thin adapters (OC, ocelot) + a standalone viewer. ocelot-desktop (Scala 3, LWJGL 3.4.3) has no plugin API; a custom display node needs a fork.
- Tests: GTNHGradle configures no test framework; add JUnit 5 yourself (Angelica: junit-bom 5.14.1). JMH targets Java 8. Keep the engine in a `:core` subproject shaded into the mod jar (Angelica's `:glsm` precedent, project classes are not relocated).
- Licensing: OC, ocelot-brain, template are MIT; ASM/ANTLR BSD-3, JOML MIT are safe to shade with notices; JvmDowngrader is LGPL-2.1 — prefer jabel.

**Java 8 target: jabel vs jvmDowngrader.** `PropertiesConfiguration` javadoc: `jabel: Jabel syntax-only support, compiles to J8 bytecode`; `jvmDowngrader: Full modern Java via JVM Downgrader (syntax + stdlib APIs)`; `modern: Native modern Java bytecode, no downgrading`. `ToolchainModule.computeToolchainVersion` maps FALSE→8, JABEL→17, JVM_DOWNGRADER→25, MODERN→25 (decoded from gtnhgradle-2.0.20.jar bytecode: `tableswitch {1:54, 2:59, 3:64, 4:64}` → `bipush 8/17/25`; the installed convention is 2.0.33 but the enum is unchanged). So with jabel, `compileJava` and `test` run on a JDK 17 toolchain while emitting major-52 classes; jabel = `com.github.GTNewHorizons:jabel-javac-plugin:1.0.2-GTNH` + `jabel-stubs:1.0.0`. Angelica uses `jvmDowngrader` with `jvmDowngraderMultiReleaseVersions = 17, 21, 25` and `jvmDowngraderStubsProvider = gtnhlib` (Angelica/gradle.properties) — that is why its jar is `Multi-Release: true` / `JvmDowngrader-Version: 1.3.5` (dev jar MANIFEST) and why GTNHLib ships `META-INF/versions/17/...` classes (gtnhlib-0.11.52.jar). For OpenGPU, jabel is the right default: the user's instance runs Temurin JRE 1.8.0_492 (instance.cfg), jabel adds no runtime dependency, and the stdlib surface stays Java 8 (no `Lookup.defineClass`, no `List.of`). Jabel mode **does** enforce the Java 8 API surface, not just the class-file version: `ToolchainModule` (gtnhgradle-2.0.20.jar, `javap -c` of the `apply` lambda) sets `sourceCompatibility`, then if `mode == JABEL` sets `CompileOptions.getRelease().set(8)` (`bipush 8`), and only for modes that `requiresModernStdlib()` sets `release` to `null`; GTNHGradle master carries the comment "For JABEL mode: set --release 8 to restrict to J8 APIs". So `List.of`/`Lookup.defineClass` fail at compile time and no animal-sniffer probe is needed for `compileJava`. A Java 8 CI run of the `:core` tests remains useful for *runtime* behaviour (the `test` task itself runs on the JDK 17 toolchain).

**ASM available at runtime.** Verified against the instance (Java 8 + LWJGL 2.9.4 path):
- `C:\Games\Minecraft\libraries\org\ow2\asm\asm-all\5.0.3\asm-all-5.0.3.jar` is the only public ASM (javap: `ASM4`, `ASM5`, `V1_8` max; `find libraries -iname '*asm*'` returns nothing else); `launchwrapper-1.12.jar` sits beside it. None of the 188 jars in `mods/` contains `org/objectweb/asm/`.
- `+unimixins-all-1.7.10-0.3.2.jar` (`Implementation-Version: 0.15.6+mixin.0.8.7`) contains **zero** `org/objectweb/asm/` classes; Mixin's ASM 9 is relocated to `org/spongepowered/asm/lib/` (149 classes; javap of the relocated `Opcodes`: `ASM4`…`ASM9`, `V1_8`, `V20`…`V26` = 70). It is Mixin-private; do not link against it.
- `gtnhlib-0.11.52.jar` ships no ASM *library* (no `org/objectweb` entries), but it does carry its own helper package `com/gtnewhorizon/gtnhlib/asm/` (`ASMUtil`, `ByteCodeUtil`, `ClassConstantPoolParser`, `SafeClassWriter`, 6 classes) compiled against the classpath ASM 5 — worth knowing before naming an OpenGPU package `asm` or assuming GTNHLib offers nothing bytecode-related.
- **Java 17–25 lwjgl3ify path (the GTNH pack, `runClient17/21/25`):** here the launcher *does* provide a modern, unrelocated ASM. lwjgl3ify's `forgePatches` jar embeds `org.ow2.asm:asm{,-commons,-tree,-analysis,-util}:9.10.1` (`forgePatchesEmbedded(libs.asm…)`, lwjgl3ify dependencies.gradle:41-45, `gradle/libs.versions.toml:3 asm = "9.10.1"`, build.gradle.kts:200-201 manifest attribute for `org/objectweb/asm/`), and RetroFuturaBootstrap declares `org.ow2.asm:*:9.9.1` as `api` without relocation (RFB master build.gradle.kts `val asmVersion = "9.9.1"`).
- On **both** paths, launchwrapper's `LaunchClassLoader` lists `org.objectweb.asm.` among its class-loader exclusions (constant strings in `javap -c`; `addClassLoaderExclusion`), i.e. that package is always loaded parent-first from whatever the launcher provides — 5.0.3 on Java 8, 9.x under lwjgl3ify. An *unrelocated* ASM 9 inside the mod jar would be silently shadowed on Java 8 and would fail at `ClassWriter`/`Opcodes.ASM9` time.
- Precedent: OC-Wasm shades and relocates `org.ow2.asm:asm{,-tree,-commons,-util,-analysis}:9.1` via `shadowImplementation` (plus a duplicated `implementation` with the comment "something in the Forgeland uses a different version of ASM … not compatible with what asmble uses", OC-Wasm-GTNH/dependencies.gradle). ocelot-brain itself depends on `org.ow2.asm:asm:9.10.1` (ocelot-brain/build.sbt:17), so the harness classpath has modern ASM; the game's ASM differs by launch path and always wins over the mod's.

Recommendation: `usesShadowedDependencies = true`, `relocateShadowedDependencies = true`, `shadowImplementation("org.ow2.asm:asm:9.x")` + `asm-commons` (GeneratorAdapter) + `asm-util` (CheckClassAdapter for tests). Relocation is mandatory, not cosmetic, because of the `org.objectweb.asm.` loader exclusion above. Emit `V1_8` class files with `ClassWriter.COMPUTE_FRAMES`; avoiding invokedynamic/`LambdaMetafactory` in generated code keeps Java 8 verification simplest. Alternative without shading: write the generator against the ASM5 API subset — workable but loses `asm-commons` helpers and forces API level `ASM5`.

**Defining generated classes.** Java 8 has no `MethodHandles.Lookup.defineClass` (JDK 9+) nor `defineHiddenClass` (JDK 15+); `sun.misc.Unsafe.defineAnonymousClass` exists only on 8–16 (removed in 17) and would break the lwjgl3ify path. The portable mechanism is a `ClassLoader` subclass calling the protected `defineClass`, exactly as OC-Wasm does: `new ClassLoader(Compiler.class.getClassLoader()) { findClass(...) { return defineClass(name, bytecode, 0, bytecode.length); } }` then `Class.forName(name, true, loader)` (OC-Wasm-GTNH/src/main/java/ca/chead/ocwasm/Compiler.java:190-204) with a bytecode-hash cache (`CACHE.putIfAbsent(new HashableByteArray(binary), r)`, Compiler.java:208-213). The parent must be the mod's loader (`LaunchClassLoader` on Java 8; `RfbSystemClassLoader` under lwjgl3ify, `-Djava.system.class.loader=com.gtnewhorizons.retrofuturabootstrap.RfbSystemClassLoader` in GTNHGradle's java17 args) so generated code links to the engine's runtime classes. One loader per compiled shader program makes programs unloadable (hot-reload, memory accounting) at the cost of a tiny per-class overhead.

**Transformers/Mixin interference.** `LaunchClassLoader` runs transformers only inside its own `findClass` (`findClass`, private `runTransformers`, `registerTransformer`, `addTransformerExclusion` — javap of launchwrapper-1.12). Classes defined by a child loader never pass through it, so Mixin/ASM transformers cannot touch generated shader classes; the engine classes they call are the already-transformed ones, which is what you want. Avoid OC-Wasm's other trick, reflectively invoking `ClassLoader.defineClass` on the mod's own loader (SyntheticFuncBuilderPatcher.java:146-148): it needs `setAccessible` into `java.lang` (opened by lwjgl3ify's `--add-opens java.base/java.lang=ALL-UNNAMED`, but gratuitous).

### 2. Running in dev (runClient/runServer, Angelica, Java 17–25)

**OC natives in dev.** The cached `OpenComputers-1.12.58-GTNH-dev.jar` contains the full native matrix under `assets/opencomputers/lib/`: `libjnlua{52,53,54}-{darwin-aarch64,darwin-x86_64,freebsd-x86_64,linux-aarch64,linux-arm,linux-x86,linux-x86_64,windows-x86,windows-x86_64}` (27 files; 736 347 bytes for `libjnlua52-windows-x86_64.dll`), plus the shaded `li/cil/repack/com/naef/jnlua/LuaState.class`, and the manifest `FMLCorePlugin: li.cil.oc.common.launch.TransformerLoader`, `FMLAT: oc_at.cfg`. `LuaStateFactory.init` resolves `classOf[Machine].getResource(s"/assets/${Settings.resourceDomain}/lib/$libraryName")`, copies it as `OpenComputersMod-<ver>-<luaver>-<lib>` into the **process working directory** (`tmpBasePath = "./"`, i.e. `run/client` under `runClient`, the game dir in the instance) — `java.io.tmpdir` is used only when `debug.nativeInTmpDir` is `true`, and both OC's default (`application.conf:1608 nativeInTmpDir: false`, "The default is to extract into the game directory"; `Settings.scala:464`) and the user's installed `config\OpenComputers.cfg:412 nativeInTmpDir=false` leave it off — then `System.load`s it (OpenComputers-GTNH/src/main/scala/li/cil/oc/server/machine/luac/LuaStateFactory.scala:213-322, path choice at :219-226; `forceNativeLibPathFirst` override at :201-209; the file is byte-identical between the local 1.12.55 checkout and 1.12.64 master). When not in tmpdir it also deletes stale siblings matching `^OpenComputersMod-.*-<lib>$` in that directory (:229-236), so `run/client` accumulates at most one native per OC version/Lua version, and the directory must be writable and executable (not a `noexec` tmpfs under CI/`xvfb-run`). This is where to look when a native "fails to load", not `%TEMP%`. Because this is a classpath lookup, it works identically under RFG's `runClient`; OC-LuaJIT's README says "Dev-run the client with OpenComputers present: `./gradlew runClient`" and its in-game validation relied on OC logging `Found a compatible native library` (LuaStateFactory.scala:322) for its own `libjnluajit52-*` placed in OC's asset namespace. OC-LuaJIT needs no `addon.gradle`; its only build customisation stages natives/kernel into resources (OC-LuaJIT/build.gradle.kts). Its `run/` dir is gitignored and contains only `natives/`.

**Working directories and local args.** `runClientWorkingDirectory` defaults to `run/client`, `runServerWorkingDirectory` to `run/server` (PropertiesConfiguration javadoc). ### 3. Headless testing with ocelot-brain

**Adapter design (recommended).**
- `opengpu-core` (pure Java 8, zero MC/OC/ocelot imports): framebuffer(s), 2D canvas, rasterizer, pipeline state, shader IR + ASM backend, a *host-neutral command interface* (`Object[] invoke(String method, Object[] args, Budget b)` or typed methods) and a `FrameListener` for observers. Everything testable with JUnit and golden images.
- `opengpu-oc` (Java, the mod): `li.cil.oc.api.prefab.DriverItem` + `prefab.ManagedEnvironment` subclass exposing `@Callback`s that delegate to core; mirror OC's own `DriverGraphicsCard` (`worksWith`, `createEnvironment(stack, host)` returning `null` on `host.world.isRemote`, `slot = Slot.Card`, `tier`, nested `EnvironmentProvider`; OpenComputers-GTNH/src/main/scala/li/cil/oc/integration/opencomputers/DriverGraphicsCard.scala:15-43) and register with `api.Driver.add(...)` in init (ModOpenComputers.scala:119-129). Client sync and rendering live here (OC's own text path: `server/PacketSender.sendTextBuffer*`, `client/PacketHandler.onTextBuffer*`, `client/renderer/TextBufferRenderCache.scala`).
- `opengpu-ocelot` (Scala 2.13, test-only): `class OpenGpuEntity extends Entity with Environment with DeviceInfo { override val node = Network.newNode(this, Visibility.Network).withComponent("opengpu").create(); @Callback def ... }`, delegating to core; needs a no-arg constructor or `NBTPersistence.registerConstructor(className, ctor)` because `NBTPersistence.load` falls back to `Class.forName(className).getConstructor()` (nbt/persistence/NBTPersistence.scala:59-67; `Ocelot.init` registers `TieredConstructor`s for its own tiered entities, Ocelot.scala:63-80). Publish frames through `EventBus.send(new OpenGpuFrameEvent(...))` (`trait Event` is a marker, event/Event.scala:6; `EventBus.subscribe(PartialFunction)`, event/EventBus.scala:31-44).
- `opengpu-viewer` (Java, Swing `BufferedImage` or LWJGL 3): subscribes to the core `FrameListener`; used both standalone (drive the engine from Java for debugging) and alongside the ocelot harness.

**Observing output in ocelot-brain.** Screen text is directly readable: `screen.data` is a `GenericTextBuffer` with `buffer: Array[Array[Int]]` and `color: Array[Array[Short]]` (util/GenericTextBuffer.scala:67-69); OC-LuaJIT's `screenText(screen)` iterates `d.get(col,row)` (OcljSmoke.scala:2151-2159). For OpenGPU the Java test holds a reference to the entity and reads the core framebuffer directly — no screen scraping needed. Keyboard input is injected by sending signals (`Keyboard.signal`, entity/Keyboard.scala:92) or `m.signal("name", …)` (Machine.scala:303).

**Harness rules from 19 (ocelot-brain 0.24.2 vs OC 1.12.64-GTNH parity).** Tick `Workspace.update()` every 50 ms, or express stall assertions in ticks — the budget reset, the synchronized-call round trip and `executionDelay` all scale with the harness cadence, and OC-LuaJIT's 25 ms loop overstates in-game throughput by up to 2× (19 §2). Run signal-queue tests at both 256 (the floor; this instance and pack 2.8.4) and 1024 (the 1.12.64 default; pack 2.9.0). Keep signal arguments to `Long`/`String`/`Double` (19 §3, §9, §13).

### 4. Testing strategy and project layout

- **Framework.** GTNHGradle configures no test framework (the plugin jar mentions `testImplementation` only in a deprecation message; retrofuturagradle-2.0.2.jar contains no test-framework configuration in its own `com/gtnewhorizons/retrofuturagradle` classes — its 27 `junit`-matching entries are all shaded third-party POMs and shaded Eclipse JDT/Mercury classes). Angelica adds `platform(libs.junit.bom)` 5.14.1 + `junit-jupiter` + `junit-platform-{launcher,engine,reporting}` + mockito 3.12.4 + archunit 1.4.1 (Angelica/dependencies.gradle.kts `afterEvaluate` block; gradle/libs.versions.toml:27-31); OC uses junit 4.13.2 + scalatest 2.11 (OpenComputers-GTNH/dependencies.gradle). Use JUnit 5 and `tasks.test { useJUnitPlatform() }` in `addon.gradle.kts`. Tests run on the toolchain JVM — JDK 17 under jabel — so add a CI job that also runs `:core` tests on a Java 8 launcher; this checks *runtime* behaviour on the user's actual JRE, not the API surface, which jabel's `--release 8` already enforces at compile time (section 1) (the shared GTNH workflow installs Zulu 8/17/21; `GTNH-Actions-Workflows/build-and-test.yml` runs `setupCIWorkspace`, `assemble`, `build` under `xvfb-run`, then a 90 s `runServer` smoke test and fails on crash reports; OpenGPU/.github/workflows/build-and-test.yml delegates to it).
- **Layout (Gradle subprojects, GTNHGradle on the root only).** Angelica is the precedent: `include("glsm")`, `include("lwjgl3-backend")`, … (Angelica/settings.gradle.kts:24-27) with `shadowImplementation(project(":glsm")) { isTransitive = false }` (dependencies.gradle.kts), and its dev jar keeps `com/gtnewhorizons/angelica/glsm/GLStateManager.class` unrelocated despite `relocateShadowedDependencies = true` — i.e. project() classes are bundled without renaming while external shaded libs are relocated. Proposed:
  - `:core` — plain `java-library`, `options.release = 8`, JUnit 5, golden-image tests, JMH (`me.champeau.jmh` or a `jmh` source set).
  - `:shader-compiler` — lexer/parser → IR → interpreter (reference) + ASM backend; depends on `:core`'s runtime interfaces; shades nothing (ASM shaded once at the root).
  - root (the mod) — `shadowImplementation(project(":core"))`, `shadowImplementation(project(":shader-compiler"))`, `shadowImplementation("org.ow2.asm:…")`; `compileOnly` OC `:api`, Angelica `:api`.
  - `:ocelot-harness` — Scala 2.13 `scala` plugin, `testImplementation(files("lib/ocelot-brain.jar"))` built from a pinned submodule with `sbt assembly` (`assemblyJarName := "ocelot-brain-0.24.2.jar"`, build.sbt:23; the `assets/opencomputers/lib` natives are kept by the merge strategy, :25-28) — ocelot-brain is not on any Maven repo, and `sbt 2.0.7` needs JDK 11+, so either commit the assembled jar to a private Maven/`libs/` or script OC-LuaJIT's `build-brain.sh` route. Its tests run on JDK 17 (brain's Java classes are major 61) and need the three `asie.pl` jars (vendor them; "Pin the commit, vendor the jars", ocelot-brain.md:54). ocelot-brain ports the same `LuaStateFactory` extraction logic: with its default `debug.nativeInTmpDir: false` (ocelot-brain application.conf:1597; Settings.scala:180) the `libjnlua*` natives are written as `Ocelot-<ver>-<luaver>-<lib>` into `Ocelot.librariesPath`, which defaults to `./` — the harness's working directory, i.e. the subproject dir for Gradle's `test` task (brain LuaStateFactory.scala:210-225; Ocelot.scala:28,45). Either set `Ocelot.librariesPath = Some(buildDir/natives)` before `Ocelot.initialize()` or keep the CWD writable/executable and gitignore `Ocelot-*`.
  - `:viewer` — Swing/LWJGL 3 app depending on `:core`.
- **Golden-image tests.** Render fixed scenes with the core API, encode via `javax.imageio` PNG (lossless), compare per-channel with tolerance 0 for integer rasterisation paths and ≤1 LSB for shaded paths; store expectations under `core/src/test/resources/golden/`; regenerate with a system property. Keep the rasteriser integer/fixed-point where possible so results are bit-identical across JDK 8 vs 17/21 and x86-64 vs aarch64.
- **Fuzzing the shader compiler.** Grammar-driven random program generator + three oracles: (1) `asm-util` `CheckClassAdapter` on emitted bytecode, (2) the JVM verifier (define the class with verification on), (3) differential execution IR-interpreter vs JIT-compiled for random inputs. Property-based testing with jqwik (Java 8 compatible) or seeded JUnit parameterised tests; cap with timeouts since generated loops can hang.
- **Benchmarks.** JMH is built with `<source>1.8</source><target>1.8</target>` (openjdk/jmh parent `pom.xml`), so `jmh-core` runs on Java 8; benchmark rasteriser fill rate, shader dispatch, and the full OC call path under ocelot-brain (OC-LuaJIT's `bench/oc/*.lua` + `OCLJ_REPS` pattern, smoke-test.sh:31-49).
- **Lua-driven integration.** `ocelot-harness/src/test/resources/lua/*.lua` programs loaded as EEPROM BIOS or `autorun.lua`; assertions on the core framebuffer, `machine.lastError == null`, and (for budget semantics) the call-budget behaviour under `computer.callBudgets`; run the matrix 5.3/5.2/LuaJIT(/5.4) under the §3 harness rules (50 ms `Workspace.update()` cadence; complete `brain.conf` with asserted values; `NativeLuaArchitecture` class assertion; no ocelot-only `getRemainingCallBudget`/`forceBind`/`latestCallBudget` in portable assertions; queue tests at 256 and 1024; signal arguments `Long`/`String`/`Double` only — 19).

## Design implications for OpenGPU

1. The engine must be a host-neutral Java 8 library with no MC/OC/ocelot types in its API; OC and ocelot adapters are thin shells (OC-LuaJIT's "one shared core with two shells" conclusion, ocelot-brain.md:80, applies verbatim). This is what makes ocelot-brain testing, the viewer, and a future ocelot-desktop fork possible.
2. The shader compiler's JVM backend must target `V1_8`, use a shaded **and relocated** ASM 9 (the launcher's `org.objectweb.asm.` is parent-first and differs between the Java 8 and lwjgl3ify paths), define classes via a private `ClassLoader` subclass with the mod loader as parent, cache by bytecode hash, and never rely on `Lookup.defineClass`/`defineHiddenClass`/`Unsafe`. Generated classes must be re-derivable from persisted shader source (OC persists machine state; ocelot's `Workspace.save/load` and OC's `Persistable` only carry NBT).
3. Compile against OC `:api` (1.12.64-GTNH; never below 1.12.58 because of the `TextBuffer.dropFile` signature change) and Angelica `:api` (2.2.21, optional, `@Optional`), run with the `:dev` jars; keep `usesMixins = false`; `forceEnableMixins = true` only in a dev profile when Angelica is on the run classpath.
4. Provide two test rigs from day one: `:core` JUnit/golden/JMH on JDK 8 and 17, and `:ocelot-harness` (Scala 2.13, JDK 17) booting a Case with the OpenGPU entity under 5.3 (what a fresh CPU runs on the pack and here) and 5.2 (the pack's declared default and the LuaJIT-compat profile) as co-equal must-pass legs, plus OC-LuaJIT, with 5.4 as a user-instance-only leg (10 F9), each pinned explicitly via `setArchitecture` and ticked at 50 ms under a complete, asserted `brain.conf` (19 §2, §9); make in-game `runClient` (Java 8/LWJGL 2) and `runClient21` (lwjgl3ify 3.0.33 under convention 2.0.33) the last validation step, as OC-LuaJIT did (in-game-tests.md). Expect OC/ocelot natives to land in the run/test working directory, not `%TEMP%`.
5. Keep all third-party code BSD/MIT; stay on jabel to avoid LGPL stubs and runtime stdlib shims.
