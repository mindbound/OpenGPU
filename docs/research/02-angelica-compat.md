# 02 — Angelica / Iris / Sodium (Celeritas) compatibility constraints for OpenGPU

Research date: 2026-10-08. Sources: local Angelica checkout at `C:\Users\astro\Downloads\Angelica` (tag 2.2.8, HEAD 6d8cbf9 2026-08-19; cited as `Angelica/<path>:<line>`), a shallow clone of the installed tag 2.2.21 (cited as `Angelica@2.2.21/...`), the installed `angelica-2.2.21.jar`, the user's `fml-client-latest.log` (run of 2026-10-06), the OC-GTNH checkout (`OC/<path>`, shallow: 1 commit), shallow clones of GTNHLib (343a327) and lwjgl3ify (c87172b), and the GitHub release notes 2.2.3–2.2.30. "Verified" means read in source or log; "inferred" is marked.

## Summary

1. Angelica is no longer a state-tracking shim over a compat GL context: since 2.1.0 (d7d2228a, #1412; 25 §2) it creates a **GL 3.3+ core, forward-compatible context** (probing 4.6 down to 3.3; with `glProfile=ES` it creates a GLES 3.2 context instead) and emulates the whole fixed-function pipeline (matrix stacks, lighting, fog, `glBegin/glEnd`, display lists, `GL_QUADS`, `glPushAttrib`) in software plus generated GLSL. The user's own log confirms: "Created GL 4.6 core profile context", backend "OpenGL (LWJGL2)", Intel Graphics, Java 8.
2. Every `org.lwjgl.opengl.GL*` / ARB / EXT / GLU call in every mod class is rewritten by a bytecode transformer to `com.gtnewhorizons.angelica.glsm.GLStateManager`. There is no per-mod opt-out: a class that escapes the transformer (classloader exclusion) calls legacy GL on a core context and renders nothing or errors.
3. The rule is therefore simple: write ordinary LWJGL2 `GL11..GL33` code, never register transformer exclusions on render packages, keep `glPushAttrib` nesting well inside the attrib-stack limit (32 in the installed 2.2.21; 18 in the older 2.2.8 checkout; the limit rose in 2.2.19, 25 §2), restore every binding you change, and stay inside the set of GL functions GLSM knows (§1). Unmapped calls pass straight to the driver on the GL backends but crash on the experimental SDL-GPU backend (user-selectable since 2.2.29); note that the unmapped-call detector deliberately ignores the LWJGL2 `GLSync` family, so sync objects are never reported (§4).
4. Iris: TESRs render in the `BLOCK_ENTITIES` phase with Iris's `gbuffers_block` program; a TESR that binds its own program detaches the Iris pass, which is re-attached only when the mod rebinds program 0 or the exact previous program. Shader packs render TESRs a second time in the shadow pass, but under the default/user config (`shadowSkipInMeshTileEntities=true`, an option that exists from 2.2.0, 25 §5.3) only for blocks whose `getRenderType()` is -1; a block with an ISBRH or a standard render type (OC screens, and the ISBRH chassis recommended in §5) is skipped in the shadow pass entirely.
5. Celeritas: chunk meshing is multi-threaded; ISBRHs run off-thread only when annotated `@ThreadSafeISBRH` and may not call `Tessellator.draw()` themselves (the call is stripped). TESRs stay on the render thread and are frustum-culled against **cached** render bounds (in 2.2.21 even baked into the chunk-section data for static TEs); the static/infinite/dynamic classification is made once per TE *class*.
6. OC-GTNH already follows these rules (`@ThreadSafeISBRH` on `BlockRenderer`, display-list-free `TextBufferRenderCache`, `glTexSubImage2D`-based `DynamicFontRenderer` as the default font path), which is the proof that "upload pixels to a GL texture, draw a Tessellator quad in a TESR" is production-safe under Angelica.
7. Safest OpenGPU strategy: CPU-side framebuffer, `glTexSubImage2D` of dirty rows once per frame on the render thread, one textured `Tessellator` quad in a TESR with explicit state save/restore. Client-side GPU shaders are feasible (`#version 330 core`, own VAO/FBO, offscreen pass outside world rendering) but add a well-defined list of extra obligations (§5).

## Findings

### 1. GLStateManager (GLSM): what it is and how other mods' GL calls get there

**What it is.** `Angelica/README.MD:16-22` states the design: "Targets GL 3.3+ core profile; FFP emulation via generated GLSL shaders; Display list emulation; Software matrix stacks and state management through GLSM; GL_QUADS → GL_TRIANGLES conversion; Automatic transformation of mod shaders that use compat-only GLSL builtins". The context is created by `Angelica/src/mixin/java/com/gtnewhorizons/angelica/mixins/early/angelica/MixinForgeHooksClient_CoreProfile.java:63` (`new ContextAttribs(3, 3).withProfileCore(true).withForwardCompatible(true)`), probing from 4.6 (4.1 on macOS) down to 3.3 (`:77-123`) and auto-pinning the result in `angelica-modules.cfg` (`pinnedGLVersion`; the user's file has `pinnedGLVersion=0`, `glProfile=AUTO`, `angelica-modules.cfg:306`, `:187`). The core path is taken whenever the effective `glProfile` is `AUTO` or `CORE`; with `glProfile=ES` (config or `-Dangelica.glProfile=es`) `createDisplay` instead creates a **GLES 3.2** context (`:51-57`, `ContextAttribs(3, 2).withProfileES`). The mixin is unconditional (`Angelica/src/main/java/com/gtnewhorizons/angelica/mixins/Mixins.java:45`) and byte-identical in 2.2.21. `RenderSystem.initRenderer` accepts an ES or a core context and throws on any non-core *desktop* context (the check is in the non-GLES branch, `capabilities.OpenGL32 && !core`): "FFP emulation requires a core profile and nothing would render" (`Angelica/glsm/src/main/java/com/gtnewhorizons/angelica/glsm/RenderSystem.java:172-184`). Verified in the user's instance: `fml-client-latest.log:5809` "Created GL 4.6 core profile context", `:5870` "GL 3.3 core profile detected, enabling FFP shader emulation", `:5866` "Max GLSL version: 4600", `:5880-5882` Intel(R) Graphics 4.6.0 Build 32.0.101.8860.

**The redirector (verified).** `Angelica/glsm/src/main/java/com/gtnewhorizons/angelica/glsm/redirect/GLSMRedirector.java` is an ASM pass. It pre-filters classes by constant-pool scan for `org/lwjgl/opengl/`, `Drawable`, `Display`, GLU types and the named extension classes (`:821`), then rewrites `MethodInsnNode`s whose owner starts with `org/lwjgl/opengl/GL` and whose name is in the map (`:873-882`), plus named-owner maps for ARB/EXT/APPLE/GLU/`OpenGlHelper`/GTNHLib `UniversalVAO`. `glEnable/glDisable(const)` with a tracked cap becomes `GLStateManager.enableBlend()` etc. (`:185-193`, `:830-860`); invokedynamic method handles are rewritten too (`:956`); `org.lwjgl.util.glu.Sphere/Cylinder/Disk/PartialDisk` are type-replaced (`:786-789`). Calls into `org/lwjgl/opengl/*` that are **not** in the map are logged once: "Unmapped GL call ... reached the redirector; on a non-GL backend this will crash at runtime" (`:114`), controlled by `-Dangelica.unmappedGL=OFF|WARN|FAIL|STRICT` (default WARN; `Angelica/glsm/src/main/java/com/gtnewhorizons/angelica/config/SystemProperties.java:26`). One deliberate blind spot: `isUnmappedGlCall` returns false for any descriptor containing `Lorg/lwjgl/opengl/GLSync;` (`:67`, `:74-79`; same in 2.2.21), so the LWJGL2 `GL32.glFenceSync/glClientWaitSync/glWaitSync/glDeleteSync` family is neither redirected nor reported under WARN/FAIL/STRICT.

**Which classes are transformed.** All classes loaded through `LaunchClassLoader` except `CORE_EXCLUSIONS` = `org.lwjgl`, `com.gtnewhorizon.gtnhlib.asm`, `com.gtnewhorizons.angelica.glsm.`, `me.eigenraven.lwjgl3ify` (`GLSMRedirector.java:177-182`), plus `com.gtnewhorizons.angelica.lwjgl3.` and `com.gtnewhorizons.angelica.transform` (`Angelica/src/main/java/com/gtnewhorizons/angelica/loading/shared/transformers/AngelicaRedirector.java:22-25`). The FML transformer is registered from a late tweaker so it runs after Mixin (`.../loading/fml/tweakers/AngelicaLateTweaker.java:56-70`); under RFB/lwjgl3ify it sorts after `mixin:mixin` and **before** `lwjgl3ify:redirect` (`.../loading/rfb/transformers/RFBAngelicaRedirector.java:38-45`). Classloader transformer exclusions registered by other coremods are honored by LaunchClassLoader, so Angelica actively *narrows* over-broad exclusions of known mods (DragonAPI, Xaero's, Ears, FoamFix, Alfheim, ...; `Angelica/glsm/src/main/java/com/gtnewhorizons/angelica/glsm/loading/EcosystemNarrowRules.java:9-89`, `TransformerNarrower.java:11-22`; config `transformercompat.*` in the user's `angelica-modules.cfg:358`; 2.2.29 added PowerConverters). The user's log shows this firing (`fml-client-latest.log:3505` "Narrowed com.fiskmods.heroes.asm transformer exclusion to allow GL redirection").

**Opt-in/opt-out.** There is no annotation or manifest flag to opt a mod *out* of GL redirection, and opting out would break it (core context). The only "opt-in" API is for callers that bypass bytecode (script engines, reflection, MethodHandles): `Angelica/src/main/java/com/gtnewhorizons/angelica/api/GLRedirects.java:10-39` exposes the redirect table and a regex to rewrite script text to `GLStateManager.*`. Angelica's own code is forbidden from calling LWJGL directly (`Angelica/src/test/java/com/gtnewhorizons/angelica/arch/NoDirectGLCallsTest.java:15-43`).

**State GLSM tracks (verified, `GLStateManager.java` / `GLContextState.java`).** Per context (`ctx()`, thread-local worker contexts since 2.2.21 "Give each GL drawable its own GLSM context", `GLStateManager.java:149-200`): boolean enables (alpha test, blend, depth, cull, lighting, texture per unit, fog, rescale-normal, scissor), blend func/equation (with a "vanilla vs effective" split that Iris overrides, `:1374-1399`), depth func/mask, color mask, clear color, stencil, viewport, line/point/polygon state, texture bindings per unit and the active unit (`glBindTexture :1963-2004`), software matrix stacks (`getModelViewMatrix() :7622`, `glGetFloat(GL_MODELVIEW_MATRIX)` answered from the stack `:1131`), attrib stack with a hard maximum depth of **32 in the installed 2.2.21** (`Angelica@2.2.21/glsm/.../GLStateManager.java:279`, confirmed by `javap -constants` on the jar's `GLStateManager.class`; the 2.2.8 checkout still has `16 + 2` = 18 at `:216`; the limit rose to 32 in 2.2.19, 53776684, 25 §2), overflow throws `IllegalStateException("Attrib stack overflow: max depth N reached")` (`:3586`; 2.2.21 `:3963`); 2.2.23 fixed "attrib stack overflow from world-less TESR item renderers", VBO/EBO/VAO bindings (`glBindVertexArray(0)` is redirected to a GLSM-owned default VAO, `:6206-6225`), pixel pack/unpack buffer bindings and unpack state (`:5855-5905`), draw/read framebuffer (`:6273-6290`), active program (`:5013-5075`, `getActiveProgram() :7666`), and a `TextureInfoCache` of texture dimensions/formats/filters. `glGetInteger` is answered from the cache for `GL_CURRENT_PROGRAM`, `GL_DRAW/READ_FRAMEBUFFER_BINDING`, `GL_TEXTURE_BINDING_2D`, `GL_ARRAY_BUFFER_BINDING`, `GL_VERTEX_ARRAY_BINDING`, `GL_VIEWPORT`, `GL_LIST_INDEX/MODE`, blend/stencil/depth enums (`:986-1065`), so save/restore through queries is correct and cheap.

**Legacy features that are emulated (so a mod may still use them).** `glPushAttrib/glPopAttrib` with every classic bit (`Angelica/glsm/src/main/java/com/gtnewhorizons/angelica/glsm/Feature.java:21-24`; `pushState :3583-3612`); `glBegin/glEnd` through `ImmediateModeRecorder` (`:2334-2357`); `glDrawArrays/glDrawElements(GL_QUADS)` through a shared quad-to-triangle EBO (`:2638-2660`, `:2495-2520`, `QuadConverter.java:22-28`); display lists through a VBO-backed command recorder (`DisplayListManager.java:48-56`; `glTexSubImage2D` with a PBO offset is unsupported inside a list, `GLStateManager.java:5316-5320`); vanilla `Tessellator.draw()` is replaced by a streaming VBO+VAO drawer with a persistent-mapped ring buffer on GL 4.4+ (`.../mixins/early/angelica/ffp/MixinTessellator_CoreProfile.java:18-21`, `.../glsm/streaming/TessellatorStreamingDrawer.java:7-12`). GLSM's FFP emulation uses generic attribute locations 0 (position), 1 (color), 2 (UV0), 3 (UV1/lightmap), 4 (normal) (GTNHLib `src/main/java/com/gtnewhorizon/gtnhlib/client/renderer/vertex/VertexFormatElement.java:58-74`).

**Mod shaders.** `glShaderSource` first runs **every** source, core or not, through `GlslTransformUtils.renameReservedWords(src, backend.getMinGLSLVersion())` (`GLStateManager.java:5232-5240`; 2.2.21 `:5822-5831`): identifiers `sample` and `new` are always renamed, and `sampler` is renamed when the backend's minimum GLSL is >= 400 (`GlslTransformUtils.java:49-58`, `:74-84`). Then, when `ShaderManager` is enabled, it applies `CompatShaderTransformer.transform`: sources without `#version`, or below 330, or using `gl_ModelViewMatrix`, `gl_Vertex`, `gl_FragColor`, `texture2D`, `attribute/varying`, ... are rewritten to 330 core with injected `angelica_*` uniforms that GLSM uploads before each draw (`CompatShaderTransformer.java:58-70`, `:117-160`; `CompatUniformManager.java:174-215`). A source whose first `#version` directive is >= 330 with the literal `core` token skips the AST rewrite and `fixupVersion` returns it as-is (`isCoreShader :167-174`, `fixupVersion :652-668`) — so "unchanged" means unchanged apart from the reserved-word renaming; a bare `#version 330` without `core` is *not* treated as core and is pattern-checked for legacy builtins. GLSM deliberately does not touch a core shader's attributes/uniforms: `ShaderManager.preDraw` returns early when `CompatUniformManager.refreshCompatUniforms` finds no registered compat uniforms for the program ("Don't emulate FFP on non-iris core shaders", `.../glsm/ffp/ShaderManager.java:125-134`; `CompatUniformManager.java:174-176`). Under the GLES profile every shader is additionally cross-compiled to ES 320 via shaderc/SPIRV-Cross (`CompatShaderTransformer.java:155`).

**Texture uploads.** `glTexImage2D/glTexSubImage2D(ByteBuffer)` unbind any tracked PBO around the call, update `TextureInfoCache`, and regenerate mipmaps only if the texture was flagged `generateMipmap` (`:2098-2116`, `:5284-5298`, `maybeGenerateMipmap :4287-4293`); the `long offset` overloads are the PBO path (`:5316-5322`). Vanilla `DynamicTexture`/`TextureUtil.uploadTexture` is not special-cased beyond a mixin that fixes `allocateTextureImpl` and filter restore (`.../mixins/early/angelica/textures/MixinTextureUtil.java`).

**Threading.** `GLStateManager.MainThread` is captured at class init (`:205-209`) and `RenderSystem` is documented as "asserting that calls are run on the render thread" (`RenderSystem.java:39`); off-thread GL from OC worker threads is not an option (it never was); all uploads must be marshalled to the client thread.

### 2. Iris shader packs

**What a TESR runs under.** `Angelica/src/mixin/java/com/gtnewhorizons/angelica/mixins/early/shaders/MixinTileEntityRendererDispatcher.java:20-42` wraps `renderTileEntityAt`: HEAD does `GbufferPrograms.pushBlendState()`, `CapturedRenderingState.setCurrentBlockEntity(id)` (block id from the pack's `block.properties`, resolved by block+meta in `TesrProviderDispatch.resolveBlockEntityId`), and `PassRebindGate.rebindIfDirty()` which re-binds the Iris pass if any earlier TESR changed the program or draw-FBO generation (`.../rendering/tesr/PassRebindGate.java:14-26`); RETURN resets and pops. TESRs run inside the `BLOCK_ENTITIES` phase (`Angelica/src/main/java/net/coderbot/iris/layer/GbufferPrograms.java:132-146`), i.e. with the pack's `gbuffers_block` program bound, sampling whatever texture unit 0 holds. Texture binds on unit 0 are reported to Iris (`.../angelica/iris/IrisGLSMBridge.java:238-246`), which looks up `_n/_s` PBR companions for the bound id (`.../iris/pipeline/DeferredWorldRenderingPipeline.java:2216-2230`); for a raw mod texture this yields default normal/specular (inferred, high confidence).

**Binding your own program during world rendering.** `IrisGLSMBridge.java:301-335` subscribes to GLSM `PROGRAM_CHANGE`: when, while `shouldOverrideShaders()` is true (`DeferredWorldRenderingPipeline.java:901`), a mod binds a program Iris does not own, Iris calls `onModProgramOverride()` (`:922-929`: current pass becomes null, the pass program id is remembered). The pass is restored by `restorePassAfterModProgram(newProgram)` (`:931-948`) **only if the next `glUseProgram` is 0 or exactly the remembered program id**; binding anything else leaves Iris detached and the rest of the world phase renders with the mod's program. Rule: capture `prev = glGetInteger(GL_CURRENT_PROGRAM)` (cached, `GLStateManager.java:1041`) and `glUseProgram(prev)` afterwards (0 also works because GLSM then re-activates FFP and Iris re-matches).

**FBOs and viewport.** Iris renders into its own G-buffer FBOs; a TESR that binds an FBO must restore `GL_DRAW_FRAMEBUFFER_BINDING`/`GL_READ_FRAMEBUFFER_BINDING` and `GL_VIEWPORT` (both cached, `:1045-1046`, `:1065`). `PassRebindGate` also tracks `drawFramebufferGeneration`, so a leak is corrected before the *next* TESR, not during yours.

**Blend state.** A mod's `glBlendFunc` is a "vanilla" request; Iris may override it with the pack's per-program blend and uses the vanilla blend to classify draws as translucent (`IrisGLSMBridge.java:274-281`, `DeferredWorldRenderingPipeline.java:897-899`). Push/pop via `glPushAttrib(GL_COLOR_BUFFER_BIT)` is the safest way to restore, but under Iris only from 2.2.8: before it, a blend, alpha-test, depth-mask or colour-mask change made while Iris holds an override lock survives `glPopAttrib`, because the pop restores the cached value directly and Iris applies its deferred request when it releases the lock (22c94799, #2017; 25 §1.3, rule R-4; the in-game effect is inferred).

**Shadow pass.** With a pack active, `ShadowRenderer.renderTileEntity` calls `TileEntityRendererDispatcher.instance.renderTileEntityAt` again for visible tile entities (`.../iris/pipeline/ShadowRenderer.java:748-818`, call at `:768`; 2.2.21 `:772-798`), but only for those that pass its filters: distance below `getMaxRenderDistanceSquared`; with `cullShadowTileEntities=true`, distance below `shadowTileEntityMaxDistance=32`; and with `shadowSkipInMeshTileEntities=true`, **only blocks whose `getRenderType()` is -1** (`:753-762`: `if (block != null && block.getRenderType() != -1) return;`, comment in `AngelicaConfig.java:347-349` "Skip tile entities whose block already renders in the terrain mesh"). All three keys live in the user's `angelica-modules.cfg` (`:46`, `:326`, `:329`), not `angelica.cfg`, and all are at their defaults. `shadowSkipInMeshTileEntities` exists only from 2.2.0; below it every visible TESR, ISBRH chassis included, is drawn again in the shadow pass (25 §5.3). Consequence: a pure-TESR block (renderType -1) is invoked up to twice per frame, so its texture uploads must be keyed to the frame, not to the call; a block with an ISBRH or standard render type — OC screens (`SimpleBlock.getRenderType = Settings.blockRenderId`) and the ISBRH-chassis design recommended in §5 — is never called in the shadow pass under this config, which also means its display emits no TESR shadow geometry at all.

**Known breakages (changelog, 2.2.9 to 2.2.30).** 2.2.12 "Fix for texture being mistakenly turned off by Iris (#2072)" and "Fixes TESR texts (travel anchors) depth test bug"; 2.2.23 "TESR state and batching leak fixes (#2162)"; 2.2.26 "Improve shader support for custom block rendering (#2176)"; 2.2.27/2.2.28 shader caching on disk. Nothing OC/Computronics/OpenGlasses-specific appears in Angelica's source or release notes (the only "opencomputers" string is a display-list debug-attribution heuristic, `DisplayListManager.java:1167`); the installed OpenGlasses/Computronics/openprinter jars contain no Angelica references and OpenGlasses's world widgets still use `glBegin` (works through emulation).

### 3. Sodium/Celeritas side: ISBRH threading, TESRs, OC's renderer

**ISBRH off-thread rules (verified).** "Vanilla render types (0-41) are thread-safe. ISBRHs (42+) need @ThreadSafeISBRH" (`Angelica/src/main/java/com/gtnewhorizons/angelica/rendering/celeritas/threading/ThreadedAngelicaChunkBuilderMeshingTask.java:27`); `canRenderOffThread` (`:95-99`) consults `AngelicaBlockSafetyRegistry`, which requires the ISBRH class to carry `@ThreadSafeISBRH` or implement `ThreadSafeISBRHFactory` (`.../rendering/AngelicaBlockSafetyRegistry.java:22-54`). Unsafe blocks are deferred to the main thread (`.../celeritas/AngelicaChunkBuilderMeshingTask.java:68`, `:380-397`; 2.2.21 "Stops chunk workers from blocking on deferred ISBRH blocks"). Off-thread meshing uses a thread-local tessellator (`TessellatorManager.enterLocalMode`, `ThreadedAngelicaChunkBuilderMeshingTask.java:106-112`), hence the API contract "Any tessellator access must be done within the methods of the ISBRH and not cached in the class" (`.../api/ThreadSafeISBRH.java:13`, `perThread` at `:34`). Independently of the annotation, `IsbrhTessellatorAbuseTransform` strips `Tessellator.draw()/startDrawingQuads()/startDrawing()` from every `renderWorldBlock` (`.../loading/shared/transformers/IsbrhTessellatorAbuseTransform.java`), so an ISBRH can only *emit quads*; it cannot issue draws, bind textures or change GL state. `ThreadedBlockData` (`.../client/rendering/ThreadedBlockData.java:5-9`) is the per-thread copy of `Block.minX..maxZ` bounds; `StateAwareTessellator` (`.../rendering/StateAwareTessellator.java`) is the mixin interface that tags each vertex with AO/shader-block state during meshing (`AngelicaChunkBuilderMeshingTask.java:124`, `:369-370`). Dynamic *pixel* content cannot live in the chunk mesh anyway (meshes rebuild only on block updates), so OpenGPU's ISBRH, if any, only draws the static chassis.

**TESRs.** Rendered on the render thread by `CeleritasWorldRenderer.dispatchTE` → `TileEntityRendererDispatcher.renderTileEntity` (`.../rendering/celeritas/CeleritasWorldRenderer.java:571-590`); the renderer map is made concurrent only because meshers *look up* renderers (`.../mixins/early/rendering/MixinTileEntityRendererDispatcher.java:21-28`). Two Angelica layers wrap each call (`.../mixins/early/angelica/tesr/MixinTileEntityRendererDispatcher.java:18-40`): (a) `TesrProviderDispatch.tryRender` for renderers implementing the opt-in `TesrMeshProvider` (cached mesh keyed by `angelica$meshKey`, rebuilt when `angelica$meshDirty`, buckets by `(VertexFormat, ResourceLocation texture, TesrMaterial)`; `.../api/tesr/TesrMeshProvider.java:9-28`; `@API "angelica|tesr"` v1 in 2.2.8, v2 in 2.2.21 adding `TesrMaterial.unfilteredAtlas()`), and (b) `BatchEligibility`, which only affects renderers that draw `ModelRenderer` parts (a plain Tessellator TESR has `parts == 0` and is left alone, `.../rendering/tesr/BatchEligibility.java:29-36`). `TesrShaders.register(name, bind, release)` plus `TesrMaterial.Builder.shader()` is the sanctioned way to run a mod-owned GL program around batched TESR draws (`.../api/tesr/TesrShaders.java:13-25`).

**TESR culling uses cached bounds.** Celeritas frustum-tests `angelica$getCachedRenderBoundingBox()` for every TE class that is not `INFINITE` or `DYNAMIC`, regardless of `section_gated_tesr_culling`; that option (true in the user's `angelica-options.json`) only decides whether the test uses the section-gated `SimpleFrustum` or `currentViewport.isBoxVisible` (`CeleritasWorldRenderer.java:390`, `:532-556`). The cache is recomputed only when x/y/z, block type or metadata change (`.../mixins/early/rendering/MixinTileEntity.java:86-110`). Two further constraints: (a) the `STATIC`/`INFINITE`/`DYNAMIC` classification is made **once per TileEntity class** from the first instance's `getRenderBoundingBox()` (`TileEntityRenderBoundsRegistry.classify`, `:33-61`), so a class must consistently return `INFINITE_EXTENT_AABB` from its very first instance or be listed in `dynamicBoundsTileEntities` (user's `angelica-modules.cfg:65-68`, not `angelica.cfg`) — a class whose first instance returns a finite box is STATIC for the rest of the session; (b) in 2.2.21, with section-gated culling on, a STATIC TE whose box fits inside its 16^3 section has that box baked into the chunk-mesh data at build time (`AngelicaChunkBuilderMeshingTask.java:199-225`, `:280`, `AngelicaBuiltRenderSectionData.culledBlockEntityBounds`) and is tested against that copy until the section is rebuilt; only "global" TEs (box spilling outside the section, or null) are tested per frame against the per-TE cache (`CeleritasWorldRenderer.java:483-494`, `:553-561`). This matters for a multi-block display whose origin TE grows without a metadata change (inferred risk, medium confidence).

**How OC-GTNH coexists (verified).** `OC/dependencies.gradle:12` compiles against `com.github.GTNewHorizons:Angelica:2.1.52:api` (transitive=false); `OC/src/main/scala/li/cil/oc/client/renderer/block/BlockRenderer.scala:3,16` annotates the ISBRH `@ThreadSafeISBRH(perThread = false)` (present in the installed 1.12.64 jar's `BlockRenderer$.class`). `OC/src/main/scala/li/cil/oc/client/renderer/TextBufferRenderCache.scala:27`: "Keep this uncached: display lists do not replay Tessellator vertex state reliably under Angelica." — screen text is re-tessellated every frame. `.../tileentity/ScreenRenderer.scala:62-98` is the pattern: `glPushAttrib(GL_ALL_ATTRIB_BITS)`, `OpenGlHelper.setLightmapTextureCoords`, disable lighting, blend, `glPushMatrix`, draw via `Tessellator.instance`, `glPopMatrix`, `glPopAttrib` (plus `GL14.glBlendColor` for distance fade, `:81-83`). The default font path (`OC/src/main/resources/application.conf:87 fontRenderer=hexfont`) is `DynamicFontRenderer`: `glGenTextures`, `glTexImage2D(RGBA8, 256x256)`, per-glyph `glTexSubImage2D(ByteBuffer)` (`.../font/DynamicFontRenderer.scala:107-158`). OC still uses display lists for robots and the GUI frame (`RobotRenderer.scala:73,105,230,237`; `gui/BufferRenderer.scala:36-87` with `glBegin/glEnd`) and GL15 VBOs for holograms (`HologramRenderer.scala:170-373`) — all of which rely on GLSM emulation and work in GTNH today.

### 4. Platform baselines: GL profile, backends, lwjgl3ify, Java 8 vs 21

**Profile.** Always core profile at least 3.3, forward-compatible (§1). Consequences for mod code even when "just using GL11": no wide lines at the driver (GLSM emulates them, `prepareLineEmulation`), no client-side vertex arrays without a VAO (GLSM keeps a default VAO bound), no `GL_QUADS` at the driver (converted), no fixed-function at the driver (emulated). `RenderSystem` capability flags: compute = GL 4.3 or `ARB_compute_shader` (`RenderSystem.java:545-551`), image load/store, SSBO, buffer storage, sampler objects (`:122-131`).

**Backends.** `BackendManager` picks the highest-priority available `RenderBackend` via `ServiceLoader` (`Angelica/glsm/src/main/java/com/gtnewhorizons/angelica/glsm/backend/BackendManager.java:25-52`). Three are shaded into `angelica-2.2.21.jar` (verified: `META-INF/services/com.gtnewhorizons.angelica.glsm.backend.RenderBackend` lists all three; `sdlgpu/` classes present): `Lwjgl2GLRenderBackend` (priority 0, always available, "OpenGL (LWJGL2)", `Lwjgl2GLRenderBackend.java:87-93`), `Lwjgl3GLRenderBackend` (priority 50, available iff `org.lwjgl.opengl.GL31C` loads, i.e. lwjgl3ify; `@Lwjgl3Aware`, calls LWJGL3 `GL*C` directly, min GLSL 330; `Angelica/lwjgl3-backend/src/main/java/com/gtnewhorizons/angelica/lwjgl3/Lwjgl3GLRenderBackend.java:58-64,135-147,169-172`), and `SDLGPURenderBackend` (priority 150, available only when `-Dangelica.sdlgpu.enable=true` **and** `SDLGPUGate.isSDLGPUAvailable()` (lwjgl-sdl, lwjgl3ify >= 3.0.25 `DisplayEvents` API, lwjgl-shaderc and lwjgl-spvc on the classpath) **and** `SDLGPUGate.isEngaged()` (window claimed via lwjgl3ify's post-window-create event), i.e. it is only reachable on an lwjgl3ify instance; `Angelica/sdl-gpu/src/main/java/com/gtnewhorizons/angelica/sdlgpu/SDLGPURenderBackend.java:474-476`, 2.2.21 `:514-516`, `SDLGPUGate.java:56-63`, `:167-171`, `SystemProperties.java:19-20`; indirect draws required, **no geometry shaders**, `:494-495`; min GLSL 460; shaders go GLSL to SPIR-V to MSL/DXBC). On the user's Java 8 instance the LWJGL3 and SDL providers "could not be instantiated" and LWJGL2 was selected (`fml-client-latest.log:5805-5808`). Release 2.2.29 (2026-10-05) "Add renderer selection to video settings — OpenGL Default and optional SDL GPU (experimental) ... includes vulkan/metal/d3d" (PR #2215), so on lwjgl3ify instances SDL GPU is one click away; there, "unmapped" GL calls crash. The `glsm`, `lwjgl3-backend` and `sdl-gpu` subprojects are also published separately on the GTNH Nexus (`com/gtnewhorizons/angelica/{glsm,lwjgl3-backend,sdl-gpu}`; `glsm` has versions 2.1.5–2.2.30). `Angelica/umbra/` is an in-tree standalone mod ("replaces Minecraft 1.7.10's legacy rendering pipeline with a modern, backend-agnostic core", `umbra/src/main/resources/mcmod.info`) that disables itself when Angelica is present (`umbra/src/main/java/com/gtnewhorizons/umbra/loading/shared/AngelicaDetector.java:6`); it is not in the 2.2.21 jar and no release was found — if it ships, the same GLSM rules apply without Sodium/Iris.

**lwjgl3ify.** `LwjglRedirectTransformer` renames every `org/lwjgl/` reference in mod bytecode to `org/lwjglx/` unless the jar manifest has `Lwjgl3ify-Aware: true` or the class carries `@Lwjgl3Aware` (`lwjgl3ify/src/main/java/me/eigenraven/lwjgl3ify/rfb/transformers/LwjglRedirectTransformer.java:30-37,58-60,104-130`). The generated `org.lwjglx.opengl.GL11...GL45`, `ARBShaderObjects`, `EXTFramebufferObject`, `GLSync` keep LWJGL2 signatures and delegate to LWJGL3 (e.g. `GL20.glShaderSource(int, CharSequence)` at `lwjgl3ify/src/generated/java/org/lwjglx/opengl/GL20.java:260`, `GL32.glFenceSync` returning `org.lwjglx.opengl.GLSync` at `GL32.java:131-134`). Because Angelica's redirector sorts *before* `lwjgl3ify:redirect`, mod GL calls become `GLStateManager` calls first and GLSM (compiled against LWJGL2, Java-8-downgraded with jvmdowngrader, `Angelica/glsm/build.gradle.kts:135-141`) talks to whichever backend was chosen. Net effect: a Java-8-bytecode mod using LWJGL2 `GL11..GL33`/ARB/EXT APIs runs unchanged on Java 8 + LWJGL2 and on Java 17–21 + lwjgl3ify (lwjgl3ify README: supported client Java 17.0.6, 19.0.2, 20, 21+).

**Is GL 2.x shaders / FBO / VBO / PBO / glTexSubImage2D safe on both stacks?** Yes, as long as the calls are in GLSM's map. Verified mapped (`GLSMRedirector.java:186-566`, `:567-760`): all of GL11 including `glTexImage2D/glTexSubImage2D/glGetTexImage/glReadPixels/glPixelStorei`; GL15 buffers including `glMapBuffer/glBufferSubData/glGetBufferSubData`; GL20 shaders/uniforms/attribs (`glUniform1..4`, `glUniform1fv/3fv/4fv`, `glUniformMatrix2..4`, `glVertexAttribPointer`, `glEnable/DisableVertexAttribArray`, `glBindAttribLocation`); GL30 FBO/RBO/VAO/`glMapBufferRange`/`glBlitFramebuffer`/`glGenerateMipmap`/`glBindBufferBase` (plus `glBindBufferRange` since 2.2.21); GL31 instancing and UBO; GL32 `glFramebufferTexture`; GL33 samplers, `glVertexAttribDivisor`, timer queries; GL42 `glTexStorage2D/glBindImageTexture/glMemoryBarrier`; GL43 `glDispatchCompute`, vertex-attrib-binding, `glMultiDrawElementsIndirect`; GL44 `glBufferStorage/glClearTexImage`; GL45 `glCreateBuffers/glNamedBufferData/SubData`; `ARBShaderObjects`, `ARBVertexBufferObject`, `EXTFramebufferObject`, `ARBFramebufferObject`, `ARBMapBufferRange`, `ARBBufferStorage`, `ARBOcclusionQuery`, `ARBSamplerObjects` (2.2.21), `OpenGlHelper.*`. Not mapped (pass-through on GL backends, crash on SDL): the LWJGL2 `GL32.glFenceSync/glClientWaitSync` family (only the LWJGL3 `GL32C` descriptors are mapped, `:769-772`), `GL30.glClearBuffer{fv,iv,uiv,fi}` (only GL43 `glClearBufferData/SubData` are present), GL40+ tessellation/indirect-count beyond the listed ones, `glDebugMessage*` (deliberately bypassed). Run dev with `-Dangelica.unmappedGL=STRICT` to catch most of these — but not sync objects: `isUnmappedGlCall` skips every descriptor containing `Lorg/lwjgl/opengl/GLSync;` (`GLSMRedirector.java:67`, `:74-79`), so LWJGL2 `glFenceSync`/`glClientWaitSync`/`glWaitSync`/`glDeleteSync` are silently passed through and would only surface as a crash on the SDL-GPU backend. Grep OpenGPU's own code for `GLSync` instead.

### 5. Pragmatic recommendation

**Baseline (safest) rendering path for a pixel display**

1. Keep a CPU-side framebuffer (direct little-endian RGBA8 `ByteBuffer`) owned by the client-side screen object; OC's Lua `gpu` calls mutate it on OC worker threads behind a lock and extend a dirty rectangle. The GL texture object is touched only on the client thread.
2. On the client thread, once per frame (frame counter or a `RenderWorldLastEvent`/`ClientTickEvent` gate, so the Iris shadow pass does not re-upload), `GL11.glBindTexture` + `GL11.glTexSubImage2D(GL_TEXTURE_2D, 0, x, y, w, h, GL_RGBA, GL_UNSIGNED_BYTE, buf)` for the dirty rows (`glPixelStorei(GL_UNPACK_ROW_LENGTH)` is mapped, so partial-width uploads from the full buffer work). Allocate once with `glTexImage2D(GL_RGBA8)`, set `GL_TEXTURE_MIN/MAG_FILTER=GL_NEAREST`, `GL_TEXTURE_MAX_LEVEL=0` (so `maybeGenerateMipmap` never fires), `GL_CLAMP_TO_EDGE`. This is byte-for-byte OC's `DynamicFontRenderer` pattern (§3). `net.minecraft.client.renderer.texture.DynamicTexture` also works; the hand-rolled texture only buys partial uploads. Registering the texture under a `ResourceLocation` in `TextureManager` additionally makes it usable from the `TesrMeshSink` bucket API later.
3. Draw in a `TileEntitySpecialRenderer`: `glPushAttrib(GL_ENABLE_BIT | GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT | GL_LIGHTING_BIT | GL_TEXTURE_BIT)` (specific bits; the nesting budget is 32 in the installed 2.2.21 — 18 in 2.2.8; it rose in 2.2.19 (25 §2) — and vanilla/other mods consume some), `OpenGlHelper.setLightmapTextureCoords(lightmapTexUnit, 240, 240)` for an emissive panel, `glDisable(GL_LIGHTING)`, bind the texture, `Tessellator.instance.startDrawingQuads(); addVertexWithUV x4; draw()`, `glPopAttrib()`. Everything is plain `GL11`/`OpenGlHelper` — redirected automatically, and the same code works without Angelica on a compat context. Do not reference `GLStateManager` directly unless Angelica becomes a hard dependency; if you want its getters, depend on `com.gtnewhorizons.angelica:glsm:<ver>` compileOnly and guard with `Loader.isModLoaded("angelica")`.
4. Block chassis via a normal ISBRH annotated `@ThreadSafeISBRH(perThread = false)` with no instance state and no `Tessellator.draw()` (compile against `com.github.GTNewHorizons:Angelica:<ver>:api`; a missing annotation class is harmless at runtime; OC does exactly this).
5. Give the display TE a stable `getRenderBoundingBox()` (or register the class in Angelica's `dynamicBoundsTileEntities` in `angelica-modules.cfg`, or return `INFINITE_EXTENT_AABB` for the origin of a resizable multi-block) because of cached-bounds culling (§3). Because classification is per class and fixed by the first instance, the choice must be consistent across all instances from the first one: do not return a finite box first and grow it later.

**Avoid**: display lists for per-frame content (works through emulation, but recording cost and OC's own warning); `glBegin/glEnd` in hot paths (emulated, slow); leaving a program, FBO, VAO or non-default texture unit bound on return; `glPushAttrib(GL_ALL_ATTRIB_BITS)` in deeply nested helpers; any transformer/classloader exclusion covering `opengpu.client.*`; caching `Tessellator.instance` in ISBRH fields; GL calls from OC worker threads; deprecated internal formats (`GL_RGBA`/`GL_ALPHA` are promoted or remapped by GLSM/GLES — use `GL_RGBA8`).

**Extra work for client-side GPU acceleration (custom GLSL / FBO / compute)**

- Author shaders as `#version 330 core` (the literal `core` token is required for GLSM to treat the source as core; a bare `#version 330` is pattern-checked for legacy builtins) and avoid identifiers named `sample`, `new` or `sampler`, which `renameReservedWords` rewrites in every source (§1); use explicit `uniform mat4` inputs; read the matrices with `glGetFloat(GL_MODELVIEW_MATRIX, buf)` / `GL_PROJECTION_MATRIX` (GLSM answers from its software stack; LWJGL2 compat answers natively). Legacy `#version 120` with `gl_ModelViewProjectionMatrix` is auto-transformed, but the explicit form avoids depending on the transformer and is GLES-translatable.
- Own VAO + VBO with `glVertexAttribPointer` on your own locations; `glBindVertexArray(0)` afterwards (GLSM maps it to its default VAO). GLSM only writes generic attributes 0–4 for FFP/compat programs, never for pure core programs (`ShaderManager.java:125-134`).
- Program discipline under Iris: `prev = glGetInteger(GL_CURRENT_PROGRAM)` ... `glUseProgram(prev)` (exact id, or 0). Never bind a different program as the "restore".
- Render-to-texture: do it **outside** the world geometry phase (e.g. in `RenderWorldLastEvent` or a tick/pre-render hook) into your own FBO, then let the TESR draw a plain textured quad. That keeps the Iris pass untouched (`shouldOverrideShaders()` is false outside level geometry), avoids the shadow-pass double invocation, and needs only GL30/EXT FBO calls, all mapped. Save/restore `GL_DRAW/READ_FRAMEBUFFER_BINDING` and `GL_VIEWPORT`; GTNHLib's `CustomFramebuffer`, `ShaderProgram`, `VAOManager`/`VertexBuffer` (`GTNHLib/src/main/java/com/gtnewhorizon/gtnhlib/client/renderer/{postprocessing,shader,vao,vbo}`) are convenient and are themselves redirected.
- Readback (for a software-visible framebuffer or screenshots) via `glReadPixels`/`glGetTexImage` is mapped; PBO readback (`GL_PIXEL_PACK_BUFFER`) is tracked.
- Compute: `glDispatchCompute`, `glBindImageTexture`, `glMemoryBarrier`, SSBO binding are mapped and gated by `RenderSystem.supportsCompute()` (GL 4.3/ARB); the user's GPU reports GL 4.6. Keep it an optional accelerator with the planned JVM-bytecode CPU path as the default, because the SDL-GPU backend treats compute specially and lacks geometry shaders, and GL 3.3-only machines are explicitly supported by Angelica.
- Testing: `-Dangelica.unmappedGL=STRICT` (does not report `GLSync` calls, §4), `-Dorg.lwjgl.util.Debug=true` (GLSM debug groups/KHR_debug), `pinnedGLVersion=33` to simulate the minimum profile, and `glProfile=ES` once (both keys in `angelica-modules.cfg`). SDL GPU needs an lwjgl3ify (Java 21) instance.

## Design implications for OpenGPU

1. **Rendering abstraction = "LWJGL2-style GL11/GL15/GL20/GL30 calls on the client thread".** Angelica needs nothing else; the same code runs on vanilla LWJGL2 compat contexts and on lwjgl3ify. Isolate GL in one client package (`opengpu.client.render`) and never exclude it from transformation.
2. **Frame-granular upload, pass-agnostic draw.** Dirty-rect `glTexSubImage2D` once per frame; TESR draws must be idempotent because Iris may call them twice (shadow pass). Under the default config this second call only happens for renderType -1 blocks (from 2.2.0, where `shadowSkipInMeshTileEntities` appeared; 25 §5.3); with the ISBRH chassis of item 5 the display TESR is skipped in the shadow pass and casts no TESR shadow (§2).
3. **State hygiene is the whole compatibility story.** `glPushAttrib` with specific bits, explicit restore of program/FBO/VAO/active texture unit; never leave `GL_TEXTURE1` (lightmap) active.
4. **Multi-block display bounds** must be stable or registered as dynamic, and the choice (finite / infinite / dynamic) is fixed per TE class by the first instance Celeritas sees (§3).
5. **ISBRH only for static geometry**, annotated `@ThreadSafeISBRH`, stateless, no draws.
6. **Shader programs are an optional tier**: `#version 330 core`, offscreen FBO pass outside world rendering, exact program restore; detect capabilities at runtime; the CPU/ASM path is the baseline.
7. **Build**: `compileOnly("com.github.GTNewHorizons:Angelica:<ver>:api") { transitive = false }` for `@ThreadSafeISBRH`/`TesrMeshProvider`; optionally `com.gtnewhorizons.angelica:glsm` for `GLStateManager` getters. Target Java 8 bytecode (Jabel) as planned; GLSM itself is downgraded to 8, so no lwjgl3ify dependency is needed.
8. **Dev/test matrix**: Java 8 + LWJGL2 + Angelica 2.2.21 (user's instance), Java 21 + lwjgl3ify + Angelica latest (GTNH default), with and without a Complementary shader pack, and once with `-Dangelica.sdlgpu.enable=true` on the Java 21 stack.
